# План: перенос поведения эталонного фронтенда в версию с бэкендом

**Эталон:** `C:\Users\user\Desktop\Web-markup-updated` (`app.js`, `index.html`, `style.css`). Это рабочий фронтенд без бэкенда.
**Цель:** всё, что есть в обеих версиях, работает так же, как в эталоне, и при этом сохраняется на сервере.
**Не трогаем:** сегментацию, загрузку и обработку снимков, индикатор прогресса ML. Всё, чего нет в эталоне, остаётся как есть (например, «Полигон по точкам»).

Как читать документ:
- `[ ]` — задача, `[x]` — сделано.
- **API** — какие существующие запросы использует пункт.
- ⚠ — нужно решение или изменение бэкенда.

Дописывайте прямо в файл: пункты, замечания, приоритеты (P1 — сначала).

## 0. Принципы (общие для всех этапов)

- [ ] **Модель данных как в эталоне.** Слои и объекты живут в памяти карты (реестр слоёв, у объекта метаданные: id на сервере, номер, имя, культура, папка).
  - Любое действие сразу применяется на карте, без перезагрузки всей карты с сервера, как сейчас.
  - Параллельно действие уходит на сервер существующим запросом. При ошибке сервера изменение на карте откатывается и появляется сообщение.
  - Полная загрузка с сервера — только при входе и восстановлении сессии.
- [ ] **Отмена и повтор (80 шагов)** с типами действий, как в эталоне: добавить объект, удалить объекты, изменить форму, объединить, добавить/удалить метку, удалить слой, удалить папку. Каждая отмена и каждый повтор — настоящими запросами к серверу.
- [ ] **Проверка после каждого этапа:** unit-тесты, сборка, прогон в браузере на подменённом API с записью всех запросов (метод, путь, тело), сверка с контрактом бэкенда.

## Решения по ходу работы

- Инструменты работают через сервер без полной перезагрузки карты: каждое изменение — один запрос
  (`POST`/`PATCH`/`DELETE`/`merge`), ответ сервера сразу заменяет объект в памяти.
- Отмена/повтор идут через те же запросы; удалённый и восстановленный объект получает новый id —
  дальнейшие отмены автоматически используют новый id.
- Метки линейки/циркуля/текста — только в браузере (как в эталоне), удаляются без вопроса и отменяются.
- «Полигон по точкам» оставлен (есть только в версии с бэком): Enter/двойной клик/зелёная точка — сохранить, Esc — отменить без сохранения.
- История действий: объекты сервер логирует сам, поэтому из интерфейса пишутся только выбор инструмента, отмена/повтор, подписи/координаты, слой из «+ Новый слой…».

- **Легенда:** как в эталоне — слои с объектами остаются в легенде, даже если скрыты галочкой (в том числе в скрытой папке).
- **История действий:** как в эталоне. Интерфейс пишет в историю и события, которые не меняют данные: выбор инструмента, отмена и повтор, подписи, подложка, dzz.by и т. п.
  - Для этого на сервере добавлен запрос **В6** `POST /api/v1/activity/`: только добавление; категории account / map_tools / export / upload_processing; текст до 300 символов; payload до 2 КБ; не чаще 120 в минуту; помечается `source: "ui"`; есть тест.
  - Изменения данных сервер по-прежнему пишет сам, дублей нет.
- **Удаление объектов:** везде с подтверждением — и клавишей Delete, и крестиком в списке. Отмена (Ctrl+Z) по-прежнему работает. Метки линейки, циркуля и текста удаляются без вопроса, как в эталоне.
