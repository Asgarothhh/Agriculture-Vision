# Датасет сегментации полей ЦПТЗ

Бинарная семантическая сегментация **поле / фон** по оцифровкам ЦПТЗ и ортофото Google Hybrid. Тайлы собраны конвейером `field_dataset_builder` из shapefile в `оцифровки ЦПТЗ/`.

Задача: по RGB-снимку предсказать, какие пиксели относятся к обрабатываемой площади поля. Внутренние пустоты (преграды, лесополосы, водоёмы, строения внутри контура) **не являются отдельным классом** — это фон.

Снимок состояния на момент описания: **14 950 тайлов z19** (сетка 204.8 м @ 0.1 м/пикс), все шесть хозяйств собраны. Поверх них конвейер дописывает сетку z18–z16 и чипы целых полей — готовые PNG z19 не перескачиваются.

## Состав и объём

Источник разметки — векторные границы полей. Снимок — мозаика Google Hybrid (`lyrs=y`, zoom 19), не GeoTIFF dzz.by. Каналов **три (RGB)**, NIR нет.

| Хозяйство | id | split | Полей (KodNum=1 / все) | Тайлов | CRS тайлов | Пустот в маске | Средняя доля поля |
|---|---|---|---|---|---|---|---|
| Должа | `dolzha` | train | 147 / 148 | 1 576 | EPSG:32636 | 532 | 0.68 |
| Савушкин Луч | `savushkin` | train | 270 / 271 | 2 148 | EPSG:32635 | 610 | 0.74 |
| Учхоз | `uchkhoz` | train | 185 / 191 | 3 071 | EPSG:32636 | 1 374 | 0.78 |
| Моас | `moas` | train | 233 | 3 277 | EPSG:32635 | 1 975 | 0.66 |
| Шипяны | `shipyany` | train | 130 | 2 095 | EPSG:32635 | 1 477 | 0.77 |
| Олекшицы | `olekshitsy` | **val** | 181 | 2 783 | EPSG:32634 | 1 326 | 0.79 |
| **Итого** | | | **1 146** | **14 950** | | | ~0.73 |

У Должи, Савушкина и Учхоза в shapefile есть атрибут `KodNum`: в датасет попали только объекты с `KodNum = 1` (поля). У Моаса, Олекшиц и Шипян колонки нет — взяты все полигоны слоя «чистая площадь».

Преграды вычитались там, где слой есть: Должа 550 полигонов, Савушкин 654 полигона + 1 линия с буфером 3 м, Учхоз 1 410 полигонов. Точечные объекты **не** вычитались (`subtract_points: false`).

Тайл **z19** попадает в датасет, только если доля чистого поля ≥ **5 %**. У сеток z18–z16 порог ниже (2–3 %), чтобы не выкинуть узкое поле на большом кадре. Чипы целых полей пишутся, пока маска не пустая.

Имена файлов:

- сетка z19 (как раньше): `{farm}_{ix:04d}_{iy:04d}.png`, например `dolzha_1727_29786.png`;
- сетка другого масштаба: `{farm}_{ix:04d}_{iy:04d}_{scale_id}.png`, например `shipyany_0012_0144_z17.png`;
- чип целого поля: `{farm}_field{idx:04d}_z{zoom}.png`, например `olekshitsy_field0042_z17.png`.

Индексы сетки — ячейки метрической сетки в CRS хозяйства, не тайлы Google XYZ. `idx` у field-чипа — порядковый номер очищенного полигона в хозяйстве.

## Структура каталогов

Корень: `field_dataset_builder/output/dataset/`.

```
dataset/
  classes.txt                 # 0 background, 1 field
  data.yaml                   # Ultralytics YOLO-seg
  manifest.csv                # один ряд на тайл
  failed_tiles.log            # только если были сбои скачивания
  train/
    images/                   # RGB PNG + .pgw рядом
    masks/                    # одноканальные PNG L + .pgw
    labels/                   # YOLO-seg .txt
    world/                    # дубликат .pgw
  val/
    images/  masks/  labels/  world/
```

Рядом с каждым PNG в `images/` и `masks/` лежит ESRI world-файл `.pgw` (в листинге каталога это выглядит как «в два раза больше файлов, чем тайлов»). Считать надо по `*.png` или по строкам `manifest.csv`.

`data.yaml` содержит **абсолютный** `path:` машины, на которой собирали датасет. На другой машине поправьте его или передайте путь в CLI YOLO явно.

## Спецификация тайла

Базовый масштаб **z19** (уже собранные 14 950 файлов):

| Параметр | Значение |
|---|---|
| Размер | 2048 × 2048 |
| Тип снимка | RGB uint8, PNG, mode `RGB` |
| Размер пикселя | 0.10 м |
| Сторона на местности | 204.8 м |
| Перекрытие сетки | 0 |
| Снимок | Google Hybrid, z = 19, репроекция в CRS хозяйства |
| Маска | PNG mode `L`, dtype uint8, значения **только 0 и 1** |

Грубые сетки и field-чипы — тоже 2048×2048 RGB + маска 0/1, но другой GSD и другой `google_zmax` (нативный зум, не даунскейл z19). Колонки `scale_id`, `gsd`, `zoom`, `chip_type` в манифесте.

Это не 512×512 Agriculture-Vision и не 4 канала RGB+NIR. Для большинства архитектур 2048×2048 целиком в батч не влезает — на обучении кропайте **только z19** или режьте на окна; field-чипы и z16–z18 **ресайзьте целиком** (см. [мультимасштаб](#мультимасштаб-и-целые-поля)).

## Классы и кодировка масок

Файл `classes.txt`:

```
0 background
1 field
```

| Значение пикселя | Смысл |
|---|---|
| `0` | фон: вне поля, дороги, лес, дворы, **дыры внутри контура поля** |
| `1` | чистая площадь поля |

Маска **не** 0/255 и **не** RGB. Обводки границ в растр не рисуются: заливка полигона, `all_touched=False`.

Для **SegFormer / UNet / DeepLab / Mask2Former** это индексы классов: `num_labels=2`, loss = CrossEntropy по `{0, 1}`. Умножать маску на 255 перед обучением **нельзя**.

Для **YOLO-seg** класс в `.txt` другой: там единственный класс **`0 = field`**. Это не баг и не противоречие `classes.txt`. В Ultralytics список классов начинается с нуля; фона как класса нет.

## Почему маски выглядят абсолютно чёрными

Маски записаны как одноканальный PNG с пикселями `0` и `1`. В любом обычном просмотрщике (включая превью в IDE) яркость 1 из 255 ≈ **0.4 %**. И фон, и поле выглядят чёрными. Это не пустые файлы.

Как убедиться, что разметка на месте:

```python
from pathlib import Path
import numpy as np
from PIL import Image

mask = np.array(Image.open("output/dataset/train/masks/dolzha_1727_29786.png"))
print(mask.dtype, mask.min(), mask.max(), np.unique(mask), mask.mean())
# uint8 0 1 [0 1]  ≈ доля поля в тайле

Image.fromarray(mask * 255).save("mask_vis.png")  # белое = поле
```

В QGIS откройте RGB и маску вместе: у обоих есть `.pgw`. Рендер маски — Unique Values, класс `1` любым ярким цветом.

Оверлей в NumPy: `зелёный канал = (mask > 0) * 255`. Не смотрите на сырой PNG как на «картинку».

Если `unique == [0]` — тайл действительно без поля (таких после фильтра 5 % быть не должно). Если `unique == [0, 1]` — всё штатно, даже когда глазу «чёрное».

## Геометрия: границы, пустоты, преграды

Источник правды — **внешний контур поля**.

1. Полигоны полей (при наличии `KodNum` — только `1`).
2. Уже существующие внутренние кольца shapefile (дыры в границе) остаются дырами.
3. Слои внутренних преград вычитаются из поля (`difference`).
4. Линейные преграды буферизуются на 3 м и тоже вычитаются.
5. Результат растеризуется: поле = 1, всё остальное = 0.

Пустота внутри поля в маске неотличима от леса за границей: оба — класс 0. Модель учится «это не обрабатываемая площадь», а не «это препятствие типа X».

Типичные пустоты в ЦПТЗ: лесополосы, кустарник, водоёмы, постройки, столбы/площадки, прочие неугодья внутри контура.

## Train / val

Сплит **по хозяйствам целиком**, без нарезки соседних тайлов одного поля в оба набора:

- **train** — Должа, Савушкин, Учхоз, Моас, Шипяны (12 167 тайлов, 81.4 %)
- **val** — только Олекшицы (2 783 тайла, 18.6 %)

Так нет утечки: модель не видит на валидации кусок того же поля, что был в train. Олекшицы — другой UTM (EPSG:32634) и другой ландшафт; val оценивает перенос между хозяйствами, а не случайный hold-out.

Своего `test` в выгрузке нет. Если нужен test, лучше держать ещё одно хозяйство целиком (например, Шипяны), а не мешать тайлы Олекшиц.

Не перемешивайте train/val «по файлам 80/20» без учёта `farm` в манифесте.

## Семантические маски vs YOLO-seg

| | PNG `masks/` | YOLO `labels/` |
|---|---|---|
| Задача | semantic segmentation | instance / contour segmentation |
| Класс поля | пиксель `1` | индекс `0` в строке |
| Дыры внутри поля | фон (`0`) | **не кодируются** |
| Несколько кусков поля в тайле | одна маска | несколько полигонов, каждый с классом `0` |
| Формат | PNG L 2048×2048 | `0 x1 y1 x2 y2 ...` в долях стороны тайла, Y сверху |

YOLO-seg **не умеет дыры**. В лейбле только внешний контур. Дыра внутри контура для YOLO будет «полем», хотя в PNG-маске это фон. Для кадастровой «чистой площади» учите семантические модели по `masks/`. YOLO-seg здесь — про внешнюю границу массива, не про внутренние неугодья.

Постобработка YOLO → вычитание дыр по семантической маске возможна, но это уже два выхода, а не один.

Координаты YOLO нормализованы по метрическим границам тайла, не по пикселям. Для квадратного тайла это совпадает с `x / 2048`.

## World-файлы и CRS

`.pgw` — шесть строк ESRI: размер пикселя по X, поворот, размер по Y (отрицательный), центр верхнего левого пикселя. CRS на диск не пишется: он в `manifest.csv` (колонка `crs`) и разный у хозяйств.

Нельзя просто сложить все PNG в один GeoPackage без учёта CRS. Для обучения CRS не нужен: модели работают в пикселях. Для выкладки предсказания на карту возьмите `.pgw` + CRS строки манифеста.

## Манифест

`manifest.csv`, колонки: `farm`, `farm_name`, `tile_id`, `split`, `coverage`, `xmin`, `ymin`, `xmax`, `ymax`, `crs`, `image`, `mask`, `worldfile`, `fields`, `obstacles`, `subtracted`, `holes`, `scale_id`, `gsd`, `zoom`, `chip_type`, `field_idx`.

`coverage` — доля пикселей класса 1. Фильтровать лёгкие/тяжёлые тайлы, строить сэмплер, считать площадь.

`chip_type` — `grid` (регулярная сетка) или `field` (один чип на кадастровое поле). `scale_id` у z19-сетки — `z19`; у field-чипа — `z{zoom}` подобранного GSD. Старые строки без этих колонок при докачке дополняются как сетка z19.

При докачке манифест **дописывается**. Перезапуск без `--overwrite` не перескачивает готовые RGB. Полная перезапись манифеста: `--fresh-manifest`.

## Как открывать и проверять

```python
import numpy as np
from PIL import Image

rgb = np.array(Image.open(".../train/images/dolzha_1727_29786.png"))
mask = np.array(Image.open(".../train/masks/dolzha_1727_29786.png"))
assert rgb.shape == (2048, 2048, 3)
assert mask.shape == (2048, 2048)
assert set(np.unique(mask)).issubset({0, 1})

# визуальная проверка
vis = rgb.copy()
vis[mask == 1, 1] = np.clip(vis[mask == 1, 1].astype(int) + 80, 0, 255)
```

Пары всегда с одинаковым stem: `images/X.png` ↔ `masks/X.png` ↔ `labels/X.txt`.

## Загрузка в код

Правила, общие для всех архитектур:

1. Маску читать как индексы, не нормализовать в `[0, 1]` для CE-loss и не делить на 255.
2. Ресайз/кроп маски — только **nearest neighbor** (`interpolation=cv2.INTER_NEAREST`, `F.interpolate(..., mode="nearest")`). Билинейка даст значения `0.3` и сломает классы.
3. Аугментации геометрические применяются к RGB и маске **одинаковым** spatial-transform, фотометрические — только к RGB.
4. Mean/std — ImageNet RGB: `mean=[0.485, 0.456, 0.406]`, `std=[0.229, 0.224, 0.225]`, если стартуете с ImageNet/ADE-весов. Не используйте 4-канальный препроцессинг Agriculture-Vision: NIR в этом датасете нет.
5. На вход сети обычно 512 или 640; 2048 оставляйте для инференса скользящим окном.

Минимальный Dataset:

```python
from pathlib import Path
from PIL import Image
import torch
from torch.utils.data import Dataset

class FieldSegDataset(Dataset):
    def __init__(self, split_dir: Path, transform=None):
        self.images = sorted((split_dir / "images").glob("*.png"))
        self.transform = transform

    def __len__(self):
        return len(self.images)

    def __getitem__(self, i):
        img_path = self.images[i]
        mask_path = img_path.parent.parent / "masks" / img_path.name
        image = np.array(Image.open(img_path).convert("RGB"))
        mask = np.array(Image.open(mask_path))  # uint8 {0,1}
        if self.transform:
            out = self.transform(image=image, mask=mask)
            image, mask = out["image"], out["mask"]
        if not torch.is_tensor(image):
            image = torch.from_numpy(image.transpose(2, 0, 1)).float() / 255.0
        if not torch.is_tensor(mask):
            mask = torch.from_numpy(mask.astype("int64"))
        return image, mask.long()
```

## Дообучение моделей

Датасет рассчитан на **fine-tune**, не на обучение с нуля. Старт: ImageNet / ADE20k / COCO-seg веса, затем этот набор. Если в проекте уже есть SegFormer с Agriculture-Vision (4 канала, класс «граница»), это **другая постановка**: там контур `boundaries/`, здесь заливка чистой площади. Голову и первый свёрточный слой (3 vs 4 канала) нужно заменить; веса энкодера можно перенести частично.

Рекомендуемый размер окна на обучении: **512** (SegFormer-B0…B4, UNet) или **640/1024** (YOLO-seg, крупные ViT). Батч подбирайте так, чтобы набрать ~8–16 тайлов-окон на шаг (gradient accumulation).

### SegFormer (Hugging Face)

- Модель: `nvidia/segformer-b2-finetuned-ade-512-512` или B4, если влезает по памяти.
- `num_labels=2`, `id2label={0: "background", 1: "field"}`.
- Decode head с ADE20k (150 классов) **не** совместим как есть — при загрузке `ignore_mismatched_sizes=True`, голова инициализируется заново.
- Вход: 3 канала. Не вызывайте код расширения patch embedding 3→4 из `ml_core/train_seg.py`.
- Loss: CrossEntropy (`ignore_index` не нужен: дыр в разметке нет) + Dice по классу `1`. Вес класса поля не задирайте: средняя доля поля ~0.73, фон не доминирует. Имеет смысл чуть поднять вес **фона** или оставить равные веса и смотреть IoU обоих классов.
- Обучение: **по `chip_type`**. Сетка z19 — случайный кроп 512 из 2048 (0.1 м/пикс). `chip_type=field` и сетки z18–z16 — **resize всего кадра** в 512/640, маска nearest; кроп снова даст фрагмент, а не целое поле. Сэмплер: ~50 % z19 / 30 % mid-grid / 20 % field (field-чипов мало — оверсэмпл). Флипы и повороты на 90° на всех типах.
- Валидация: IoU/Dice на **field-чипах Олекшиц** (сценарий «AOI всего поля») плюс sliding window по тайлам z19. Кроп-only val занижает ошибку и на длинных границах, и на зуме.
- Инференс крупного зума: скользящее окно 512/1024, overlap 25–50 %, усреднение softmax. Инференс выделенного поля (letterbox в 512) совпадает с train на field-чипах.
- LR: энкодер `1e-5…5e-5`, голова `1e-4`. Cosine, warmup, fp16. 20–40 эпох с early stopping по mIoU на Олекшицах.
- Не подменяйте z19 даунскейлом 2048→512: на 0.1 м/пикс тонкие лесополосы слипнутся, а целое поле так всё равно не появится. Грубый масштаб — отдельные чипы с нативным Google-зумом.

Пример настройки процессора Hugging Face: маски оставить `long`/`int64` с значениями 0/1; `reduce_labels` из ADE **выключить** (он вычтет 1 из маски и превратит фон в 255).

### YOLO-seg (Ultralytics)

```bash
yolo segment train \
  data=field_dataset_builder/output/dataset/data.yaml \
  model=yolov8s-seg.pt \
  imgsz=640 \
  epochs=100 \
  mosaic=1.0 \
  close_mosaic=10
```

- Один класс `field`. Файл `data.yaml` уже в корне датасета; поправьте `path:`.
- `imgsz` 640 или 1024. 2048 в YOLO обычно избыточен.
- Помните про дыры: метрика YOLO будет оптимизировать внешний контур. Для «чистой площади» сверяйтесь с PNG-масками, не только с `box/mask mAP`.
- Copy-paste / mosaic в Ultralytics включены по умолчанию — для полей это полезно (см. аугментации).
- Не кладите `masks/*.png` в `labels/`: Ultralytics ждёт txt-полигоны.

YOLOv8/11/26-seg отличаются скоростью; постановка данных одинаковая.

### Другие семантические архитектуры

| Архитектура | Как использовать этот датасет |
|---|---|
| **U-Net / U-Net++** (SMP, encoder ResNet/EfficientNet) | PNG-маски 0/1 напрямую. Кроп 512–1024. Хороший сильный baseline на ортофото. |
| **DeepLabv3+** | То же; ASPP хорошо берёт крупные поля. Output stride 16, decoder upsample к кропу. |
| **HRNet / SegFormer / Mask2Former** | Mask2Former: конвертировать маску в COCO-panoptic/instance (каждый связный компонент поля — instance) либо semantic-only. Для дыр semantic проще. |
| **PSPNet / FCN** | Допустимы, но слабее на длинных прямых границах, чем SegFormer/DeepLab. |
| **SAM / SAM2 / HQ-SAM** | Не учится как semantic-seg из коробки. Можно: (1) promptable fine-tune на внешних контурах; (2) дистилляция SAM как teacher. Дыры SAM часто «закрашивает». Для чистой площади предпочтительнее обычный semantic fine-tune. |
| **mmsegmentation** | Custom dataset type, `reduce_zero_label=False`, `img_suffix=.png`, `seg_map_suffix=.png`, 2 класса. |

Мультикласс (культура, залежь, лес) этот датасет **не содержит**. Не пытайтесь вытащить тип угодий из маски 0/1.

## Аугментации

Ортофото сверху, поля без канонической ориентации, сильный сезонный и радиометрический разброс (разные даты Google, пашня / всходы / стерня), швы мозаики, подписи Hybrid-слоя. Геометрия границ жёсткая (кадастр), не «органика» как кроны деревьев.

Пространственные трансформации всегда с `mask_interpolation=cv2.INTER_NEAREST`.

### Необходимые (ставить по умолчанию)

Их нет в снимке как естественного разнообразия внутри одного хозяйства, а на инференсе ориентация и экспозиция будут другими.

| Аугментация | Зачем | Рекомендация |
|---|---|---|
| HorizontalFlip, VerticalFlip | Сверху нет «верха кадра». Границы пашни одинаково валидны после отражения | `p=0.5` каждая |
| RandomRotate90 | Сетка тайлов произвольна относительно рядов | `p=0.5` |
| RandomResizedCrop / RandomCrop 512–1024 из 2048 | Только для `chip_type=grid` и `scale_id=z19`: сохранить 0.1 м/пикс | crop 512–1024. Для field/z16–z18 — `Resize` 512, не кроп |
| Яркость / контраст | Разное время суток и сезоны, пашня vs зелень | `RandomBrightnessContrast`, лимиты ±0.2, `p=0.5` |
| Цветовой сдвиг (умеренный) | Тип культуры, влажность почвы, баланс белого мозаики | Hue ±10°, Saturation ±0.2, `p=0.3` |
| Нормализация ImageNet | Совместимость с pretrained RGB-энкодером | всегда на train и val |

Пример Albumentations для SegFormer 512:

```python
import albumentations as A
from albumentations.pytorch import ToTensorV2
import cv2

train_tf_z19 = A.Compose([
    A.RandomCrop(512, 512),
    A.HorizontalFlip(p=0.5),
    A.VerticalFlip(p=0.5),
    A.RandomRotate90(p=0.5),
    A.RandomBrightnessContrast(0.2, 0.2, p=0.5),
    A.HueSaturationValue(10, 20, 10, p=0.3),
    A.Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225)),
    ToTensorV2(),
])

train_tf_field = A.Compose([
    A.Resize(512, 512, interpolation=cv2.INTER_LINEAR),
    A.HorizontalFlip(p=0.5),
    A.VerticalFlip(p=0.5),
    A.RandomRotate90(p=0.5),
    A.RandomBrightnessContrast(0.2, 0.2, p=0.5),
    A.HueSaturationValue(10, 20, 10, p=0.3),
    A.Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225)),
    ToTensorV2(),
])
# маска: тот же Compose, Resize с interpolation=cv2.INTER_NEAREST
# (в Albumentations задайте отдельно через additional_targets / mask interpolation)

val_tf = A.Compose([
    A.CenterCrop(512, 512),  # для полной val лучше sliding window без кропа
    A.Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225)),
    ToTensorV2(),
])
```

`ToTensorV2` оставляет маску целочисленной — так и нужно.

### Релевантные для спутниковых полей (желательно)

| Аугментация | Зачем | Как |
|---|---|---|
| Малый поворот ±15° | Ряды и границы не кратны 90° | `Affine(rotate=15)` или `Rotate(15)`, `border_mode=REFLECT`, маска nearest, `p=0.3` |
| Сдвиг / scale | Поле обрезано краем тайла на инференсе | `ShiftScaleRotate(shift=0.05, scale=0.1, rotate=0)` |
| Гауссов шум | JPEG/WebP Google, сжатие тайлов | `GaussNoise`, `p=0.3` |
| JPEG compression | Те же артефакты мозаики | `ImageCompression(quality_range=(60, 100), p=0.3)` |
| Лёгкий blur | Дефокус / ресамплинг при warp в UTM | `GaussianBlur(3–5)` или `MotionBlur`, `p=0.2` |
| Gamma | Тёмные весенние сцены vs летние | `RandomGamma(80–120, p=0.2)` |
| Градиентная «тень» / затемнение половины кадра | Солнце, облачная тень | `RandomShadow` или своя маска яркости, `p=0.2` |
| Дымка | Атмосфера, влажность | `RandomFog` очень слабо или умножение на 0.85–1.0 + серый, `p=0.15` |
| CoarseDropout / GridDropout | Локальные облака, пропуски мозаики, силос, техника на поле | дыры **не** переносить на маску как «не поле»: dropout только по RGB, маска без изменений. Иначе модель решит, что облако = не поле, и на чистом снимке будет дырявить пашню. `p=0.2`, отверстия 32–128 px |
| Mosaic (YOLO) | Несколько хозяйств/контекстов в одном батче | штатный mosaic Ultralytics |
| TTA на валидации/инференсе | Флипы и 90° бесплатны геометрически | 4–8 views, среднее softmax |

### Осторожно / не использовать

| Аугментация | Почему вредна здесь |
|---|---|
| ElasticTransform, GridDistortion, OpticalDistortion | Границы полей — прямые кадастровые линии. Сильная «резина» учит невозможную геометрию. |
| Perspective / PiecewiseAffine | Снимки уже орто; перспективных фасадов нет. |
| CutMix / сильный MixUp двух тайлов | Смешивает несвязанные поля и маски; граница становится физически ложной. Лёгкий MixUp (α≤0.2) спорный — лучше без него. |
| ChannelShuffle / RGBShift на десятки единиц | Ломает цвет почвы/растительности, на котором модель может опираться. |
| Случайный grayscale как единственный канал постоянно | Редкие облачные сцены ок (`p≤0.05`), не как база. |
| Downscale 2048→512 **z19** без кропа как единственная геометрия | Теряется 0.1 м/пикс, тонкие лесополосы слипаются. Грубый масштаб давайте отдельными чипами z16–z18 / field, не этим ресайзом. |
| Билинейный ресайз маски | Дробные классы. |
| Аугментации NIR / rgb_dropout из Agriculture-Vision | Четвёртого канала нет. |
| RandomCrop, который может выкинуть всё поле | После фильтра 5 % на полном тайле кроп 512 из края с coverage 0.05 может дать пустую маску. Либо отвергайте кропы с `mask.mean() < 0.01`, либо используйте RandomResizedCrop от области поля. |

Практичный минимум для z19: **Flip H/V + Rotate90 + RandomCrop 512 + BrightnessContrast + Normalize**. Для field-чипов замените RandomCrop на Resize 512 (маска nearest). Смесь обоих нужна, иначе модель снова не увидит целое поле.

## Метрики

Считайте по классу **field** и среднее по двум классам.

- **IoU (Jaccard)** класса 1 — основная.
- **Dice / F1** пиксельный.
- **IoU фона** — чтобы модель не закрасила всё полем (при доле поля 0.73 это реальный риск).
- **Boundary IoU / Hausdorff** по контуру — если важна точность границы для кадастра.
- Не используйте accuracy: 73 % «всегда поле» выглядит хорошо и бесполезно.

Валидация на полном z19-тайле 2048: прогон окна с overlap и сшивка, затем IoU по Олекшицам. Отдельно считайте IoU на **field-чипах** val (resize в 512 как на инференсе AOI). Кроп-only val занижает ошибку на длинных границах и на малом зуме.

Порог 0.5 по softmax/sigmoid класса field. Для тонких лесополос иногда лучше чуть поднять порог фона (то есть снизить порог field), если дыры «заплывают».

## Ограничения и ловушки

1. **Маски «чёрные»** — значения 0/1, не пустота.
2. **YOLO не видит дыры** — для чистой площади смотрите PNG.
3. **Нет NIR** — веса 4-канального SegFormer из этого репозитория не вставляются без обрезки канала.
4. **Google Hybrid (`lyrs=y`)** может содержать подписи и элементы карты поверх снимка. Модель не должна учить текст как признак поля.
5. **Разные даты и швы** внутри хозяйства: соседние XYZ-тайлы иногда с разным сезоном. Аугментации по яркости это частично покрывают, идеальной радиометрии нет.
6. **Класс не «сельхозугодье vs лес», а «чистая площадь данного контура»**. Лес за границей и лесополоса внутри — оба фон, но пашня соседа, если она не в shapefile, тоже фон. Модель учится вашим контурам ЦПТЗ, а не универсальному «это пашня».
7. **Сплит по хозяйствам.** Хороший IoU на Олекшицах важнее, чем на случайных 20 % Должи.
8. **Точки (столбы и т.п.) в маску не вырезались.** Мелкие точечные объекты могут остаться классом field, если не были дырой в полигоне.
9. **`data.yaml` с абсолютным путём** нужно править при переносе.
10. Не открывайте маски как RGB и не сохраняйте их JPEG — появятся артефакты и значения ≠ {0,1}.
11. **Не кропайте field-чипы.** Кроп 512 из чипа целого поля снова даёт фрагмент. Смотрите `chip_type` в манифесте.

## Мультимасштаб и целые поля

Тайлы z19 покрывают ~205 м при 0.1 м/пикс. SegFormer на кропе 512 видит ~51 м края поля и ломается, когда на карте выделяют **целое поле**: фронт снимает AOI на z15–z18 (до 4096 px) и letterbox в 512, контур становится в 1–3 пикселя.

Поэтому поверх z19 (его **не** пересобирают) пишутся:

1. **Сетка z18 / z17 / z16** — тот же `iter_tiles`, больший GSD, Google-зум совпадает с GSD (`google_zmax` 18/17/16), не даунскейл Hybrid z19.
2. **Чипы `chip_type=field`** — padded bbox каждого полигона, GSD = сторона / 2048, чтобы поле целиком влезло в кадр. Маска — все поля ЦПТЗ в кадре (класс 1), целевое доминирует. Имя `{farm}_field{idx:04d}_z{zoom}.png`.

Загрузчик **обязан** ветвить геометрию по манифесту: z19 → RandomCrop, field и грубые сетки → Resize. Сэмплинг ~50/30/20. Val — field-чипы Олекшиц.

## Пересборка

Из корня репозитория, тот же Python, что ставил `field_dataset_builder`:

```bash
python -m field_dataset_builder inventory
# только сетка z19, как раньше (готовые PNG пропускаются)
python -m field_dataset_builder build --backend google --labels --farms dolzha --scales z19 --no-field-chips
# грубые сетки + чипы целых полей (z19 не трогает)
python -m field_dataset_builder build --backend google --labels --field-chips --scales z18,z17,z16
# проверка на одном хозяйстве
python -m field_dataset_builder build --backend google --labels --farms shipyany --scales z17 --field-chips --max-tiles 5 --preview-every 1
```

Повторный запуск **пропускает** уже скачанные RGB. `--overwrite` качает заново. `--fresh-manifest` стирает CSV. Сбои сети пишутся в `failed_tiles.log`; тайл без PNG доберётся следующим запуском. Без `--scales` собираются все масштабы из `config.yaml`; field-чипы по умолчанию как `dataset.field_chips.enabled` (`--field-chips` / `--no-field-chips`).

Альтернатива снимков: `--backend dzz` (HTTP Basic в `secrets.yaml`). Размер тайла и маски те же, внешний вид снимка другой — для обучения лучше не смешивать Google и dzz в одном сплите без пометки источника.
