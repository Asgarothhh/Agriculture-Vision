# Спецификация проекта
Проект представляет собой веб-приложение для внутреннего использования компанией с целью автоматизации процесса разметки сельско-хозяйственных угодий (задача сегментации). В основе функционала сегментации заложены дообученные модели SegFormer и YOLO-26; бэкенд разрабатывается на основе фреймворка FastAPI, а также celery и RabitMQ с целью достижения асинхронности при выполнении сложных задач (например, процесс сегментации моделями глубокого обучения) в фоном режиме и построения высокопроизводительных систем с привлечением очередей задач.

### Задачи
1) Первая задача включает в себя настройку структуру проекта, а именно его бэкенд части. Для бэкенда данного проекта выбрана сервисно-ориентированная структура, основной идеей которой является разбиение проекта на отдельные сервисы, независимые друг от друга. Цель такой структуры: лёгкая масштабируемость и тестируемость. 
Ниже представлен пример сервисно-ориентированной структуры: 
```
project/
├── app/
│   ├── users_service/
│   │   ├── __init__.py
│   │   ├── main.py
│   │   ├── models.py
│   │   └── routers/
│   │       └── users.py
│   ├── tasks_service/
│   │   ├── __init__.py
│   │   ├── main.py
│   │   ├── models.py
│   │   └── routers/
│   │       └── tasks.py
│   └── __init__.py
├── tests/
│   ├── __init__.py
│   ├── test_users.py
│   └── test_tasks.py
├── .env
├── .gitignore
├── main.py
├── pyproject.toml
├── README.md
└── requirements.txt
```
Задача состоит в анализе текущего проекта, проектировании межсервисного взаимодействия и построения на основе этого сервисно-ориентированной структуры. Входные данные - текущие файлы проекта; выходной результат - тот же проект, организованный по каталогам в структуру, пример которой представлен выше (допускаются измнения в коде, если того требует разработанная схема взаимодействия сервисов, и ни при каких иных обстоятельствах).
